## How to emit a metric — `apps/api` (ts-server)

**This app's FireWeave files:** control points `apps/api/src/fireweave/control-points.ts`; start `apps/api/src/fireweave/start.ts`, imported first by `apps/api/src/app.ts`; stamps `.fireweave/stamps.ts`.

**Client:** `otel-sdk`

**Import, as it appears in this repo:** `import type { BusinessMetric, Telemetry } from "@keel/otel";`

**Counter:** `requests.add(1, attributes) // and business[signal.business].add(1, attributes) for keel.card.created / keel.card.moved / keel.comment.created / keel.card.starred`

**Histogram / timing:** `duration.record(signal.durationMs, attributes)`

**Where the instrument comes from:** packages/otel/src/index.ts startTelemetry(): counters/histogram created on a MeterProvider; apps/api/src/observe.ts's observe() Hono middleware calls telemetry.record({...}) per request, which is the single call site that drives both

**Wrapper to prefer over the raw client:** telemetry.record(signal) in packages/otel (Telemetry.record), fed by observe(telemetry) Hono middleware in apps/api/src/observe.ts — prefer adding fields to the signal object passed to telemetry.record(...) over calling otel instruments directly

**Tag / label convention (including the cohort key):** signalAttributes(signal) in packages/otel/src/index.ts derives attributes from { method, route, status, runId, actor, journey, step, pace }; business metrics are additionally gated on signal.business matching one of keel.card.created | keel.card.moved | keel.comment.created | keel.card.starred plus an expected status code
