Keel implementation · 6 Nov 2026

Implementation plan

Twelve phases. Each phase has the files, the routes, the bodies, and the test script that must pass before the next phase starts.

The product decisions are in the plan. How the pieces behave is in the explanation. This page is what to build.

How to use this

Build in order. A phase is finished when its script exits 0 and the scripts of the earlier phases still exit 0. The script is the contract. A green UI with a failing script is an unfinished phase.

Phases 1 through 4 are the board, and they correspond to milestone M1 in the plan. Phases 5 through 12 correspond to M2 through M9, in that order. The board is the product the later phases rehearse, so its client keeps a local store and asks the API only for what changed.

Shared contract

Every phase uses this envelope. A later phase adds routes. It does not invent a second error shape.

Stack

TypeScript, Node 22, pnpm 9, Hono, Vite, React, React Router, Zod, Vitest, Playwright, Postgres 16. The web and Studio are single-page apps. A navigation inside either app swaps a route component. The document loads once.

Ids and time

New ids are ULIDs with a prefix: card_, cmt_, ses_, run_. Seed ids are fixed words, listed in phase 1, so a test can name them. Timestamps are ISO-8601 in UTC. Versions and the board revision are integers that start at 1 and only increase.

Error body

Every 4xx and 5xx JSON body has this shape. The message is for a person. The code is for the client and the test.

{
  "error": {
    "code": "invalid_title",
    "message": "Title is required."
  }
}
CodeStatusWhen
invalid_body400Zod rejected the JSON, a query, or a header.
invalid_title400Title is empty or longer than 200 characters after trim.
invalid_comment400Comment body is empty or longer than 2000 characters.
invalid_credentials401Email or password does not match. Both failures use this one message.
unauthenticated401Cookie missing or expired.
forbidden403The role cannot do this. A viewer’s move is this code.
not_found404Board, card, or run does not exist.
conflict409If-Match is behind the card’s version. The body also includes card.
idempotency_replay200Not an error. A repeated Idempotency-Key returns the original success body with this code in a header, x-keel-idempotent: replay.

Session cookie

Name keel_session. HttpOnly, SameSite=Lax, Path=/. Max-Age 43200. Secure when KEEL_ENV=production. The database stores the SHA-256 of the token, never the token. A mutating browser request sends Origin equal to KEEL_WEB_ORIGIN or KEEL_STUDIO_ORIGIN. A request with a different Origin is 403 forbidden. The runner is not a browser: it sends the cookie and the run headers, and it omits Origin.

Run headers

Optional on every board route. Organic use omits them. The API copies whatever is present onto the log, the span, and the metric attributes.

The board owner can create a team and add people to it. A person on a team can move a card whose author is on that same team. Changing the title still follows the edit row. The seeded cast shares no team, so Grace still cannot move Ada’s card and Linus still cannot move one.

Revision rules

A successful create, move, title edit, or comment runs in one transaction. It increments boards.revision by 1 and sets the touched card’s version, and the new comment’s version when there is one, to that new revision. Positions are integers. A create uses max(position) + 1024 in the target column, or 1024 when the column is empty. A move between two neighbors uses the integer midpoint. When the gap is 1, the handler renumbers that column to 1024, 2048, 3072 and returns every renumbered card in shifted.

POST /cards

Headers: cookie, Idempotency-Key, Origin from the browser. Body:

{
  "boardId": "launch",
  "title": "Check the collector",
  "column": "todo"
}

201:

{
  "card": {
    "id": "card_01JQZX8K0C3F8Y0A6S2N7M4P9R",
    "boardId": "launch",
    "title": "Check the collector",
    "column": "todo",
    "position": 4096,
    "authorId": "user_grace",
    "createdAt": "2026-11-06T06:40:00.000Z",
    "updatedAt": "2026-11-06T06:40:00.000Z",
    "version": 2
  }
}

Title is trimmed. Empty or whitespace is 400 invalid_title. Longer than 200 is the same code. column outside the three names is 400 invalid_body. A missing Idempotency-Key is 400 invalid_body. The same key and the same user and the same body hash return the original 201 body and set x-keel-idempotent: replay, and they do not insert a second card. The same key with a different body hash is 409 conflict.

PATCH /cards/:id

Header If-Match is the version the client holds. Body is one or both of column and title:

{ "column": "doing" }

200:

{
  "card": { "id": "card_01", "column": "doing", "position": 4096, "version": 3 },
  "shifted": []
}

The card object in the response is a full Card, not a patch. shifted is a list of full cards whose positions changed because the column was renumbered. When If-Match is not the current version, the status is 409:

{
  "error": {
    "code": "conflict",
    "message": "The card changed.",
    "card": { "id": "card_01", "column": "todo", "version": 4 }
  }
}

card on a conflict is the full current card. The client replaces its copy with that object.

POST /cards/:id/comments

Header Idempotency-Key. Body:

{ "body": "Queue is draining." }

201:

{
  "comment": {
    "id": "cmt_01JQZX9M2E4G0Z1B7T3P8N5Q0S",
    "cardId": "card_01",
    "body": "Queue is draining.",
    "authorId": "user_grace",
    "createdAt": "2026-11-06T06:41:00.000Z"
  },
  "card": { "id": "card_01", "version": 4 }
}

The nested card is the full card after the version bump, so the store can replace that one card. Empty body is 400 invalid_comment. Replay follows the same idempotency rule as create.

GET /cards/:id

Cookie required, any role. 200:

{
  "card": { "id": "card_01", "title": "Draft the README", "version": 1 },
  "comments": []
}

Comments are oldest first. This is the drawer fetch. The board list does not include comments.

GET /search

Query q, trimmed, length 1 to 80. 200:

{
  "query": "readme",
  "cards": [
    { "id": "card_01", "title": "Draft the README", "column": "todo", "version": 1 }
  ]
}

Match is case-insensitive substring on title, limit 20, ordered by updated_at descending. Each item is a full card. An empty q is 400 invalid_body. Search does not change revision.

GET /boards/:id/changes

Query since, an integer, the revision the client already applied. 200:

{
  "revision": 4,
  "cards": [],
  "comments": [],
  "removedCardIds": []
}

When the board revision is still since, the three arrays are empty. The client keeps every card object it already holds. When the revision has moved, cards contains only cards whose version is greater than since, comments contains only comments whose version is greater than since, and removedCardIds stays empty in this version of Keel because cards are not deleted. since missing, negative, or greater than the current revision is 400 invalid_body.

Phase 4 Web stores and screens

The board is a single-page app. The document loads once. After that, sign-in, opening a card, creating, moving, commenting, and searching update local stores. A screen reads the store. It asks the network only for the slice it does not have, or for the revision delta.

Document and routes

Vite builds one index.html. The dev server and, later, the image rewrite every app path to that file so a hard refresh on /boards/launch boots the app. Inside the running app, links use the client router. No link sets window.location to a Keel path. No handler calls location.reload.

Create and comment generate the idempotency key in the client and keep it on the pending mutation until the response arrives. A double submit reuses the key. A 409 on create from a key reuse with a different body surfaces as an error on the form and leaves the store as it was. While a mutation is in flight the card row shows the pending title or column from a pending map, and the pending entry is deleted when the response is applied. A failed 400 removes the pending entry and shows the message from error.message.

The poll pauses when document.visibilityState is hidden and runs once immediately when the tab becomes visible.

Screens

What each request records

After the handler returns, and also when it returns a 4xx or 5xx, the API emits:

  • Counter http.server.requests, plus one.
  • Histogram http.server.request.duration, in milliseconds.
  • A log line with the method, the route template, the status, and the run attributes that were present.
  • A server span named with the route template.

Attributes on all three: http.route is the template, /cards/:id, never the raw card id. Also http.request.method, http.response.status_code, service.name=keel-api, service.version the git sha, deployment.environment from KEEL_ENV, keel.signal=app. Run headers, when present, become keel.run_id, keel.actor, keel.journey, keel.step, keel.pace. The exporter drops cookie and authorization before the batch leaves the process.

Business counters, each plus one, same attributes, on success only:

  • keel.card.created on 201 from POST /cards.
  • keel.card.moved on 200 from PATCH /cards/:id when column changed.
  • keel.comment.created on 201 from the comment route.

The API may emit a name only when packages/catalog/metrics.yaml lists it. A name that is not listed fails the process boot.

Header x-keel-fault: once on POST /cards, when the process has not thrown yet for that header value, throws after the card is saved and produces a 500. The card remains. A second request with the header does not throw. The default, with the header absent, never throws.

Phase 6 Accounts and prove

OpenObserve is the first vendor, and it is an account Keel connects to. Keel does not run an OpenObserve server. The prove script is the phase gate.

Config

KEEL_COLLECTOR_VENDOR=openobserve selects collector/vendors/openobserve.yaml. The fragment has two exporters. The app exporter uses KEEL_VENDOR_APP_ENDPOINT and KEEL_VENDOR_APP_API_KEY. The infra exporter uses the infra pair when those are set. An empty infra pair uses the application account. The same key in both slots is allowed, and so is a different account. Routing is on keel.signal. The rendered file keeps the key in the environment and does not copy the secret.

Host CPU, memory, Postgres connections, database size, and collector queue are scraped by the collector about every 15 seconds, marked keel.signal=infra, with no run id.

Prove

pnpm prove --run <id> queries the app org for a log and a span carrying that run id, and queries the infra org for a log carrying that run id. It exits 0 only when the app org has both and the infra org has neither. It also checks that http.server.request.duration is queryable in the app org. With the vendor on debug, prove reads the collector log instead and prints not exported, and that path is what this phase’s script asserts in CI.

  2. Render with the same key in both slots, and again with a different infra account. Both renders exit 0. The split render sends infra through its own exporter.
  3. Debug prove for a fresh run id exits 0 and prints not exported.
  4. When KEEL_COLLECTOR_VENDOR=openobserve and both keys are set, prove for a demo run id exits 0. Otherwise the script prints skipped: no vendor and exits 0.

The production host in the committed file is the real hostname when the team has one. A start whose URL host disagrees with the named target is 400 invalid_body and the runner is not spawned.

POST /runs

{
  "target": "local",
  "mode": "computer",
  "journey": "create-card",
  "pace": "demo",
  "seed": "phase7-seed",
  "confirm": ""
}

pace is demo, office, real-time, or machine. confirm must be the string production when the target is production, and must be empty otherwise. Production starts at one actor and ten minutes. 201:

{
  "run": {
    "id": "run_01JQZY0N3F5H1A2C8U4Q9P6R1T",
    "target": "local",
    "mode": "computer",
    "journey": "create-card",
    "pace": "demo",
    "seed": "phase7-seed",
    "scale": 10,
    "status": "running"
  }
}

POST /runs/:id/pause and /runs/:id/stop

Empty body. 200 with the run object, status of paused or stopped. Stop deletes the runner’s session cookies.

GET /runs/:id/events

Server-sent events. Each event is one JSON object:

{
  "at": "2026-11-06T06:50:00.000Z",
  "actor": "grace",
  "step": "add-card",
  "status": 201,
  "errorCount": 0
}

Studio’s runStore appends events. The page does not poll the document and does not refetch /targets on each event. The live strip reads runStore.

Journeys shipped in this phase

sign-in, read-board, create-card, forbidden-move. Each file has a ui block and an api block and a thinkMs range. The computer executor runs the api block. create-card signs in as Grace and posts the body from phase 3. forbidden-move signs in as Linus and expects 403.

The runner’s clock is seeded. Demo is one actor, scale 10, about three minutes. Office is Ada, Grace, and Linus, scale 10, about fifteen minutes. Arrivals are a Poisson draw, session length is lognormal, and about three percent of journeys stop before the last write. About two percent take the empty-title or viewer-move path. The same seed and the same pace produce the same step list.

Phase 8 Person

The same YAML files run in a browser. One actor. Headless by default.

Executor

mode: "person" on POST /runs starts Playwright. One browser context for the actor. The ui block is the source of clicks: goto, see, click by visible label, fill by label at 40 to 120 ms per character. The runner attaches the run headers to the browser context so the API records the run id. A failed step writes a screenshot under generated/person/<runId>/. Headed is "headed": true on the run body.

POST /otel

This phase adds the browser proxy on the Keel API. The web sends OTLP to POST /otel on the API origin. The handler forwards the body to the collector and holds no vendor key. The browser span for a click carries keel.signal=app. Cookie and authorization are stripped before forward.

Phase 10 Local-prod

The same board, API, Studio, Postgres, and collector run from images. Source mounts are absent. File watch is absent.

Images

Dockerfiles for keel-web, keel-api, and keel-studio. The web image serves the built SPA and falls back to index.html for client routes. The API image runs node on the compiled output and migrates on boot. Compose healthchecks gate order: Postgres, then API /ready, then web and Studio. ./scripts/up local-prod uses infra/compose.local-prod.yaml and host ports 4200, 4201, 4202, 42532, and 4518. It builds when the image is missing or KEEL_REBUILD=1. KEEL_ENV=local-prod. Local keeps its own compose file and ports, so the two stacks do not share a database.

Phase 11 Production

One Linux server runs the same compose file. GitHub Actions builds, pushes, and rolls forward. Rollback is the previous image tag.

Workflows

ci.yml on pull requests runs pnpm check, builds the images without pushing, and validates the rendered collector config. deploy.yml on main pushes to the registry with OIDC, SSHes with a pinned known_hosts entry, runs docker compose pull and up -d, and curls the public /ready. It records the image tag. workflow_dispatch with input image_tag redeploys that tag. Secrets live in the GitHub environment production and are written to a root-only file on the server. The workflow does not start a Studio run.

doctor fails when KEEL_ENV=production and KEEL_SEED_PASSWORD is still keel-local-only. Studio’s production target host is not a loopback address.

Phase 12 Other vendors

Datadog and Sentry are collector fragments. Application code stays as it is. doctor records which of metrics, logs, and traces each endpoint accepted.

Fragments

collector/vendors/datadog.yaml and collector/vendors/sentry.yaml follow the same two-exporter shape as OpenObserve. Switching vendor is KEEL_COLLECTOR_VENDOR plus a restart. Sentry’s traces and logs are the dependable path. When the metrics export is refused, doctor writes the refusal and does not copy the metric onto the other account.

Keel implementation. Twelve phases, one script each. The board keeps a local store and loads the revision delta. Later phases rehearse that board. They do not replace it.
